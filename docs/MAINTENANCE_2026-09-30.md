# 全工程代码维护与上位机界面更新

维护范围是整个小车工程：车载驱动、状态机、控制参数、Flash、串口协议、启动和构建配置、电脑工具及测试。UI 优化针对电脑上位机。沿用 JDY-31 与八路灰度适配后的工作目录，保留已有接线和未提交的功能改动。

随后新增的遥控回车、PID 同页速度监看与闭环测试见 [REMOTE_SPEED_2026-09-30.md](REMOTE_SPEED_2026-09-30.md)。本记录下方数量与 FLASH 用量保留本轮维护完成时的结果，最新验证以该功能说明为准。

## 上位机界面与通信

界面重新组织为实时监测、调试控制、PID 调参、通信日志四页，统一字体、卡片、状态颜色和间距。实时监测显示八路通道、三路距离、硬件/故障、电机与舵机数据，并增加目标/实测轮速趋势；滚动页面支持较小窗口。串口优先作为默认连接，旧 BLE 入口按需显示。顶部持续保留停止按钮与 Esc 快捷键。

原 GUI 同步请求会在串口等待时阻塞 Tk。现拆为：

| 文件 | 职责 |
| --- | --- |
| [host/gui.py](../host/gui.py) | 界面状态、输入校验、后台结果处理与控制权限 |
| [host/ui.py](../host/ui.py) | 页面、样式、八路图示与轮速绘图 |
| [host/session.py](../host/session.py) | 单一后台线程独占连接，串行执行握手/请求/关闭 |
| [host/protocol.py](../host/protocol.py) | 协议校验、COM 链路和协议仿真 |

后台会话用 generation 丢弃换连接、取消或退出后的迟到结果，并释放迟到连接。遥测和 DRIVE 合并排队请求，避免积压；STOP 优先执行并取消当前会话所有尚未执行的请求，防止旧 AUTO ARM 在停车后启动。已执行且等待响应的请求无法被 STOP 中途打断，仍受传输超时约束。

手动驱动仅允许硬件就绪的 DEBUG 模式，松开、移出按钮或窗口失焦时提交零 PWM。断开仅在已确认 DEBUG 时尝试 STOP，自动模式继续车端流程。PID 修改仅允许硬件就绪且处于 IDLE，成功后读回实际值；断开清空旧遥测和参数。查询、Flash 操作和关闭都在后台执行。

通信日志按 TX/RX/错误着色，可输入单行命令或执行快捷只读查询。画面约保留 500 行，导出保留最近 2000 条；原始 STOP/IDLE 也使用优先停止队列。

## 车载代码修复

| 范围 | 问题与处理 |
| --- | --- |
| UART 指令接收 | 夹带 NUL 的整行可能执行合法前缀。现在丢弃含 NUL/非法控制字符的整行，保留 CRLF 和模块日志过滤。 |
| 自动终点识别 | 终点保持时间跨过超声暂停或避障阶段后，可能在恢复时立即完成。现在中断巡线确认时清零，恢复后重新连续确认。 |
| PID 参数 | 设置参数和持久化校验的限值表重复。合并为同一描述表，补全参数边界和非法数值覆盖。 |
| Flash | 复查记录格式、Sector 11 保留、校验与提交标记；补损坏记录回退和满区保护测试。 |
| 系统输入输出 | 未定义弱控制台 hook 可能跳转到空地址。缺 hook 明确报 ENOSYS；补参数、描述符、部分读写、NULL、无文件系统和 Picolibc 路径处理。stdio 不混入车控串口。 |
| 退出 | `_exit` 进入停机循环前先关闭电机。 |
| 堆内存 | `_sbrk` 补下界与整数溢出保护，覆盖 `PTRDIFF_MIN` 和分配失败后状态不变。 |
| 构建 | 主 CMake 明确仅启用 C/ASM，移除空 include/define/link-directory 配置块。 |

同时审查电机方向/PWM/STBY、舵机脉宽、编码器回绕、三路超声捕获/超时、八路灰度扫描/缓存、控制周期、main/MSP/IRQ、GPIO/定时器映射、HAL 源引用、startup、linker 和 CubeMX 配置。未发现可安全删除的运行组件；保留 HAL/CMSIS、启动文件、库接口与生成器配置，避免破坏驱动和重新生成流程。

## 协议、诊断与冗余处理

- 旧 BT24 实现归档到 [host/legacy](../host/legacy/README.md)，保留 GUI、只读测距和 BLE 诊断能力；入口改为 `python -m host.legacy.ble_check`，导入为 `host.legacy.ble_link`。
- 主依赖只保留 pyserial，BLE 依赖拆到 [requirements-ble.txt](../host/requirements-ble.txt)；JDY-31 不需要 Bleak。
- 删除仿真器重复的 PID 默认值，统一初始化/恢复来源。修正无效距离、查询时的驱动看门狗、硬件故障和协议错误码的一致性。
- 命令只接受非空可打印 ASCII，最多 90 字符；NUL、DEL、TAB、CRLF 在发送前拒绝，连接仍可继续使用。
- COM 链路检查完整写入、完整响应、额外响应和关闭状态。传输异常使会话失效并关闭，输入错误及固件 ERR 保留连接；清理失败不会覆盖首个错误。
- PID/控制/编码器解析补边界检查；`target_ticks` 三位小数舍入后必须大于零。
- 诊断工具输出不覆盖已有报告，关闭异常仍保存已获取的诊断结果。
- 原 GUI 的页面构建和连接线程重复逻辑由视图/后台会话替代；更新 README 的入口、页面名称和维护路径。
- 官方例程保留在 `docs/modules/line_sensor/reference` 作为参考，不复制进固件构建。历史资料继续用于追溯。

## 验证与使用

执行 `.venv/Scripts/python.exe tests/run_tests.py`：6 个原生 C 测试程序与 75 项 Python 测试通过，无跳过。覆盖状态机、驱动、PID/Flash、系统调用/堆、协议/CLI、BLE、连接取消与优先停止、Tk 控制器及接线一致性。诊断工具测试使用可控时钟，避免真实睡眠边界造成不稳定轮次断言。

新增 10 项真实 Tk 事件循环测试使用隐藏窗口和仿真链路，验证初始化/断开清理、慢连接和慢遥测时窗口继续处理事件、驱动释放/失焦归零且不恢复旧命令、STOP 取消排队启动、PID 权限/读回、旧固件 HW 查询兼容以及灰度与距离输入。Tk 不可用的环境会跳过 GUI 组，本次本机实际运行通过。

窗口默认 1180 × 840，最小 1000 × 700；逐页检查内容尺寸和滚动区域，PID/监测/调试内容宽度可容纳。Windows 截图工具在识别 Python 应用时报告应用标识不一致，未完成截图视觉复核；上述事件循环和尺寸检查正常。

Debug 与 Release 编译、链接、HEX/BIN 生成通过，`nm` 无未定义符号。当前 FLASH 用量分别 62504 / 45760 B，RAM 用量 4160 / 4112 B；输出在 `build/Debug`、`build/Release`。构建和测试结果不能代替板上电气与机械验收。

运行 `start_gui.cmd` 可打开新版界面，先点“界面仿真”检查显示。未烧录实车，JDY-31 配对/四针供电、灰度方向/极性、编码器方向、舵机/电机响应和赛道参数仍按 [模块更新说明](MODULE_UPDATE_2026-09-30.md) 与 [PINOUT](../PINOUT.md) 联调。
