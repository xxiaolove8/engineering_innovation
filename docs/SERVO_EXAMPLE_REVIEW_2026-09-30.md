# DS3218MG 舵机与官方例程交叉核对（2026-09-30）

## 已确认的信息与结论

用户晚间补充：实际型号为 **DS3218MG**，电源模块输出 **5 V**，但电源负极**没有和 STM32 共地**，而且不确定板上烧录的是哪个程序。额定电流、带载电压和当前 PE9 实测波形尚未确认。

未共地是已确认的接线问题：PWM 高低电平需要以舵机负极为参考，仅连接 MCU 信号线而不连接公共地，无法保证舵机接收到有效的控制脉冲。这能解释“舵机已上电、有声音，但不响应控制”；接好后仍须确认实际固件和波形，不能宣称已经完成实车验证。

官方 STM32、51、Arduino 例程与现有 F407 源码支持相同的基本控制方式：约 20 ms 周期、1500 µs 中位，用高电平脉宽控制位置。没有发现需要额外发送“舵机解锁命令”、提高信号到 5 V，或重写现有 TIM1 驱动的依据。保留当前 1300–1700 µs 转向保护范围。

## 先修正实际接线

断电后连接：

```text
电源模块 +5 V ───────── 舵机正极（红线）
电源模块 GND ─────┬──── 舵机负极（棕线或黑线）
                  └──── STM32 GND
STM32 PE9 ───────────── 舵机信号（橙线或白线）
```

线色依据工程内数据表的两种线束图，实际仍以模块丝印和线束定义确认。载板定义为 J1-1=GND、J1-2=+5V、J1-3=PWM；核心板 PE9 对应 H1-36。舵机继续由模块供电，PE9 只接信号；不要把 5 V 接到 STM32 的 3V3 引脚。

工程内 [DS3218 数据表](DS3218%20datasheet.pdf) 第 1 页标型号 DS3218(Red)，供电 4.8–6.8 V；第 2 页给出 500–2500 µs、中心 1500 µs、50–330 Hz，控制信号图标 3.3–5 V。因此 5 V 标称供电、F407 的 3.3 V 信号和当前 50 Hz 设置均有该资料支持。数据表存在 180°/270°版本，不能仅凭“DS3218MG”确定角度版本，也不能把此表的全部电流参数当作所有 MG/Pro 变体的保证。

本地数据表的 5 V 堵转电流为 1.8 A。电源标称 5 V 不代表带载一定稳定；接好公共地后若仍异常，应测舵机插头正负极之间的带载电压。父目录未发现实际电源模块的独立规格书，不能由例程确认电源额定电流。

## 与官方单舵机程序对照

关键源文件已按原字节保存到 [reference](modules/servo/reference/README.md)，原始路径与哈希见 [archive_manifest.json](archive_manifest.json)。以下行号指对应的原始内容。

| 项目 | 官方 STM32 “单舵机” | 当前小车工程 |
| --- | --- | --- |
| 芯片 / 计时 | F103，72 MHz，TIM2 PSC=71，每计数约 1 µs | F407，TIM1 时钟 168 MHz，PSC=167，每计数 1 µs |
| 输出方式 | 定时中断轮流拉高/低普通 GPIO，实际是 8 路 | TIM1_CH1 硬件 PWM，1 路转向 |
| 引脚 | PA0–PA3、PB3–PB6 | PE9 / AF1 |
| 周期 | 每路约 2500 µs 时隙，8 路合计约 20 ms | ARR=19999，20 ms / 50 Hz |
| 上电行为 | 自动交替 1000/2000 µs，约每秒换一次 | 1500 µs 回中，等待有效的调试或自动控制 |

- [single_f103_main.c](modules/servo/reference/single_f103_main.c) 第 2–3 行标明芯片和引脚；第 16、21 行是默认 1500 µs 与 TIM2 初始化；第 25/29 行自动切换 1000/2000 µs；第 130–152 行是生效的中断输出逻辑。不能把 PSC=71 或这些 PA/PB 引脚直接搬到 F407。
- [single_stc15_main.c](modules/servo/reference/single_stc15_main.c) 使用 P0 的 8 路软件 PWM，第 84–87 行的 20.4184 重装系数是该 STC 内部时钟的经验校准，不能用于 F407。
- [single_arduino.ino](modules/servo/reference/single_arduino.ino) 使用 D10 和 `writeMicroseconds()`，自动扫描位置。第 27 行下限为 **50 µs**，与第 24 行注释的 **500–2500 µs** 不一致；没有照搬这个范围。安装了转向机构的小车也不应照搬全行程自动扫描。
- [single_arduino_ps2.ino](modules/servo/reference/single_arduino_ps2.ino) 的 `#indexPpwmTtime!` 是控制器串口协议，最终仍通过 PWM 控制舵机。DS3218MG 的信号线不是 UART，不需要这个字符串。

官方程序上电自动往返，与当前工程默认保持中位的表现不同。如果舵机原本就在中位，正常 1500 µs 输出也不会出现明显移动。

## 与多路控制器及蓝牙资料交叉

- F103 控制器的 [controller_f103_timer.c](modules/servo/reference/controller_f103_timer.c) 第 148 行起同样使用 TIM2 中断软件 PWM；TIM3/4 是电机 PWM。`controller_f103_gpio.c` 第 132 行起实际只映射 6 个舵机引脚，不能把它当作 F407/PE9 示例。
- [controller_f103_main.c](modules/servo/reference/controller_f103_main.c) 第 127–137 行在启动舵机定时器之前检查 W25Q64，缺少芯片时会停在鸣响循环。直接烧到没有配套外设的板子上，不会生成预期的舵机 PWM。第 635 行起解析 `#000P1300T500!` 等控制器命令；P 是 µs 脉宽，T 是插值时间。
- 51 控制器的 [controller_stc15_timer.c](modules/servo/reference/controller_stc15_timer.c) 才是舵机定时输出，`controller_stc15_pwm.c` 是电机 PWM。其主程序先启动舵机定时器再检查存储器，因此检查失败时可能保持中位，却不处理后续命令。
- Arduino 控制器 [controller_arduino.ino](modules/servo/reference/controller_arduino.ino) 第 128 行附近上电 attach 后又 detach；[controller_arduino_servo.ino](modules/servo/reference/controller_arduino_servo.ino) 处理命令时重新 attach，完成后再次 detach。不能把该例程当作始终连续输出 PWM 的参考。
- JDY-31 配套 [jdy31_f103_main.c](modules/servo/reference/jdy31_f103_main.c) 的实际初始化只有 OLED、LED 和 Serial，接收 0x01/0x02 控灯；没有调用 `Servo_Init()` 或 `PWM_Init()`。包里虽有 PWM/servo 文件，运行这个 main 并不会启动舵机；附带 PWM 实际使用 F103 PB9/TIM4_CH4，其注释中另有 PA7/TIM3 字样，应以调用代码为准。
- 控制器目录的“注意事项.png”“命令表.png”实际描述 MP3 文件与播放器命令，不是 DS3218MG 舵机控制资料，未作为舵机依据。

## 当前源码中影响测试的条件

1. **初始化要成功。** `Core/Src/car_hw.c:136–143` 先启动三路测距计时器、检查微秒时钟，再启动舵机；之前失败时，PWM 尚未开始。`HW?` 可查 `HW 1 READY`，或 `HW 0 RANGE_L/RANGE_C/RANGE_R/CLOCK/SERVO_PWM/...` 的具体阶段。无回波本身不等于定时器初始化失败。
2. **输出使能已存在。** `Core/Src/main.c:201–227` 设置 PSC=167、ARR=19999、CCR1=1500、PWM1 高有效；MSP 配置 PE9 AF1。`car_hw.c:143` 已调用 `HAL_TIM_PWM_Start()`，真实 HAL 会开启 CC1E、MOE、CEN，不缺高级定时器主输出使能。
3. **业务逻辑会回中。** IDLE、FAULT、FINISHED 每 10 ms 应用 1500 µs；STOP 也回中但不关闭舵机 PWM。在正常主循环中临时修改一次 CCR，很快就可能被覆盖。
4. **DEBUG 需要续发。** `DRIVE 0 0 1400` / `DRIVE 0 0 1600` 可只调舵，左右电机保持零；500 ms 未收到续发命令会回中。GUI 按住按钮时每 200 ms 续发，松开、失焦或换页后提交零电机和中位。PID 页的 `SPEED` 测试固定回中，应在“调试控制”页测舵机。
5. **PE9 共用资源已处理。** GPIO 初始化前 PG10 拉高，保持 SRAM 未选中；工程未启用 FSMC。没有发现后续把 PE9 改回 SRAM 功能的源码调用。

此前 [SERVO_CHECK](SERVO_CHECK_2026-09-30.md) 记录曾读到 VTOR=0x1FFF0000、TIM1 时钟关闭，当时板子运行 Bootloader。它是历史现场证据；本次没有连接 ST-Link 复查，不能据此断言板子现在仍运行 Bootloader。

## 接好后按此顺序复测

1. 断电接好公共地，确认 PE9 信号与舵机电源正负极无误；BOOT0 设为 0，再启动明确的小车应用固件。当前烧录版本未知，源代码正确不等于板上正在运行这些代码。
2. 连接真实的 JDY-31 出站 COM 或 USB-TTL，收到 `PING → PONG 2`，检查 `HW? → HW 1 READY`。这能确认运行兼容协议的应用与初始化状态；界面仿真不能确认实车，`PONG 2` 也不能区分所有历史 v2 固件。
3. “停止 / 待机”后进入“调试控制”，左右电机均设为 **0**，先设置舵机 **1400 µs** 并按住“驱动 / 调舵”，再试 **1600 µs**；松开回到 **1500 µs**。先确认小幅动作，不改变当前机械限幅。
4. 仍不动时，测 **舵机插头信号对舵机负极**：周期应约 20 ms，高电平宽度应随操作从 1500 改为 1400/1600 µs。若 PE9 有波形而插头没有，查接线；若两处均无波形，查实际固件、初始化和引脚；若插头波形正确，继续查带载供电、机械卡滞及舵机本身。

万用表在正常中位 PWM 下可能只显示约 `3.3 × 1.5 / 20 = 0.25 V` 的直流平均值，不能据此判断峰值不足。啸叫或保持力也不能代替 PWM 波形检查。

本次补充了 GUI 的零电机调舵提示、资料归档与对照步骤；未修改 TIM1 参数、转向限幅或看门狗，未烧录、复位或发送实车运动命令。实际共地后的复测结果待用户确认。
